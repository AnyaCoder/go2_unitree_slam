## 2. 冷启动完整命令

正常使用时只运行一键入口：

```bash
cd ~/go2_unitree_slam
./nav/start_far_real.sh
```

它按顺序完成清理、旧控制链禁用、同步狗端导航文件、狗端 UnitreeSlam、狗端 go2_nav（含安全闸）、电脑端固定地图/FAR/RViz。
需要停止时运行：

```bash
cd ~/go2_unitree_slam
./nav/stop_real_all.sh
```

下面拆成三个终端的内容仅用于排障和查看各进程原始日志。

### 2.1 狗端：启动 UnitreeSlam 常驻服务

终端 A：

```bash
ssh -t go2-wifi
cd /unitree/module/graph_pid_ws
./0_unitree_slam.sh
```

保持该终端运行。`0_unitree_slam.sh` 会启动 `QT_Server/UnitreeSlam` 常驻服务；不要另外启动另一套 `demo_mid360`、FAR、RViz 或重复的 LIO-SAM。

### 2.2 狗端：启动唯一的局部规划与底盘执行链

终端 B：

```bash
ssh -t go2-wifi
cd /home/unitree/go2_nav
./run_nav.sh live
```

保持该终端运行。它会启动狗端 `terrainAnalysis`、`terrainAnalysisExt`、
`localPlanner`、`pathFollower` 和 `nav_safety_gate.py`。`pathFollower` 的运动请求先发往
`/nav/path_follower_request`，只有安全闸在 IMU、初始位姿、定位、Goalpoint 和 path
全部满足时才转发到 `/api/sport/request`。不要绕过安全闸，也不要改回 dry-run 话题。

### 2.3 电脑端：启动固定地图和真机可视化

终端 C：

```bash
cd ~/go2_unitree_slam
./nav/run_real_view.sh
```

保持该终端运行。该脚本完成：

```text
启动狗端只读关节桥，并启动状态/waypoint/initial-pose 三个桥
启动电脑端真实状态接收器
启动本地固定 PCD、pcdMapSim、terrain、localPlanner、pathFollower、FAR
使用 nav/far_real.rviz 打开 RViz
```

### 2.4 在 RViz 提交真实起点并等待门控放行

先让狗站稳并保持完全静止约 3 秒，等待 `/livox/imu` 完成静止校准。然后在电脑端 RViz 中选择：

```text
2D Pose Estimate
```

然后在地图上按住，拖到狗当前所在位置并对准狗头朝向，松手。

只操作一次即可。初始化桥会自动：

```text
1. 向 /qt_command 发送 command=6，启动重定位；
2. 等待 lio_sam_ros2_globalLocalize 输出 Map Optimization Started；
3. 地图初始化完成后，把刚才点选的位姿发送到 /initialpose。
```

不要在固定 5 秒时发送初值。本次故障就是首张地图尚未加载完，初值发得太早；现在改为等待 `Map Optimization Started` 就绪信号。

在 `goal_commands_ready=true` 之前，狗端 waypoint 桥会拒绝 Goalpoint 和 `/way_point`。看到狗端 `Pose initialization successful` 或 `Initializing Succeed` 后检查：

```bash
ssh go2-wifi
source /opt/ros/foxy/setup.bash
source /home/unitree/autonomy_stack_go2/install/setup.bash
timeout 3 ros2 topic echo /nav/safety_status std_msgs/msg/String \
  --qos-reliability reliable --qos-durability transient_local
```

只有 `goal_commands_ready=true` 才允许点 FAR Goalpoint；点选后还要等 `motion_ready=true`，才会放行 `Move(1008)`。

如果狗端重定位已经成功，只是起点点错了，不需要重启整套服务。直接在 RViz 再次使用：

## 5. 禁止的旧操作

不要用下面这些方式代替正常流程：

```text
在狗端按 z
启动 demo_mid360
手工发送 command=8
手工伪造 /state_estimation
启动 spaceViz 或人工可走区
用实时扫描替代固定地图
```

本次实测中，`command=8` 在重定位未完成时被狗端拒绝：

```text
The current system state is not init pose.
```

真正有效的是 `command=6` 启动重定位，以及地图初始化完成后提交 `/initialpose`。`command=7` 是原厂状态机内部路径；当前电脑端桥使用等价的 `/initialpose` 入口，不需要手工发送。

### 7.1 FAR 控制权必须唯一

重定位脚本
`/unitree/module/graph_pid_ws/src/QT_Server/shell/re_location.sh`
原本会启动 `go2_control_by_sdk send_cmd` 和
`navigation_without_nav2_qt_test.launch.py`，后者再启动
`dog_control_B1_one`。这是 UnitreeSlam 的旧运动控制链，不属于 FAR 架构。

`navigation_without_nav2_qt_test.launch.py` 本身仍是 LIO-SAM 和初始位姿的宿主，
不能整个停掉；FAR-only 处理只移除其中的运动控制节点。当前已通过
`nav_dog/disable_legacy_control.sh` 完成：

```text
re_location.sh: 禁用 go2_control_by_sdk send_cmd
src/task/launch/navigation_without_nav2_qt_test.launch.py: 保留 LIO，禁用 dog_control_B1_one
install/task/share/task/launch/navigation_without_nav2_qt_test.launch.py: 同样处理
```

必须同时修改 `src` 与 `install/share`，因为 `ros2 launch task ...` 实际读取
install/share。UnitreeSlam 更新或重装后重新执行：

```bash
cd ~/go2_unitree_slam
./nav_dog/disable_legacy_control.sh
```

使用 FAR 时，狗端运动控制权只能来自：

```text
电脑 FAR -> TCP 8899 -> 狗端 localPlanner/pathFollower
  -> /nav/path_follower_request -> nav_safety_gate -> /api/sport/request
```

以下命令必须没有输出，否则禁止让狗进入运动模式：

```bash
pgrep -af '[d]og_control_B1_one'
pgrep -af '[g]o2_control_by_sdk.*send_cmd'
```

ROS 节点 `/dog_control` 也必须不存在。`nav/check_real_chain.sh` 已把这些作为强制
FAIL 检查。

`0_unitree_slam.sh` 已经负责 UnitreeSlam、雷达与重定位；不要为了“补服务”再手工拉起第二套 LIO/Livox。
