## 1. 架构

```text
电脑：固定 PCD -> pcdMapSim -> terrain -> FAR -> 全局路径
狗端：Livox/LIO -> terrain -> localPlanner -> pathFollower -> 底盘
链路：TCP 8898 状态上行；TCP 8899 路径下行；TCP 8900 初始位姿
```

狗端不运行 FAR。电脑端不运行 `localPlanner/pathFollower`。

## 5. RViz 提交起点

在 RViz 中选择 `2D Pose Estimate`，在地图上拖出狗位置和狗头朝向。

初始化桥随后：

```text
1. 向 /qt_command 发送 command=6；
2. 等待 lio_sam_ros2_globalLocalize 就绪；
3. 等待首张全局地图加载；
4. 把点选的 /initialpose 发给狗端。
```

不要固定等 5 秒后手工抢发初值。首张地图加载可能更慢。

`initialpose_link` 不发布 `/way_point`。狗端公共 `/way_point` 只由
`global_path_receiver.py` 发布。

## 6. 防 `(0,0)` 和旧路径

启动时必须满足：

```text
localPlanner 初始 goalX/goalY = NaN
global_path_receiver 是狗端唯一 /way_point 发布者
电脑端不发布公共 /way_point
电脑 FAR 的本机 waypoint 重映射为 /far/way_point
无有效全局路径时发布当前车体位姿
全局路径超过 2 秒未更新时重新发布当前车体位姿
狗端不运行 FAR
```

因此：

```text
重定位成功但尚未点 Goalpoint -> 停在当前位置
电脑 FAR 生成路径 -> TCP 8899 -> 狗端 /way_point -> localPlanner 正常走
路径清空或断流 -> 狗端目标收回当前位置
```

如果狗在无人下发目标时仍移动，立即停栈并检查：

```bash
cd ~/go2_unitree_slam
./nav/check_real_chain.sh

ssh go2-wifi
ros2 topic info -v /way_point
ros2 param get /localPlanner goalX
ros2 param get /localPlanner goalY
ps -eo pid,args | grep -E '[d]og_control_B1_one|[g]o2_control_by_sdk.*send_cmd|[f]ar_planner'
```

## 7. 下发目标

确认重定位成功后使用 RViz `Goalpoint`：

```text
电脑 RViz Goalpoint
  -> 电脑 /goal_point
  -> 电脑 FAR（固定 PCD）
  -> /viz_path_topic
  -> global_path_sender
  -> TCP 8899
  -> 狗端 global_path_receiver
  -> /way_point
  -> 狗端 localPlanner
  -> /path
  -> pathFollower
  -> /api/sport/request
```

目标不再跨 TCP 直接进入狗端 FAR；跨网络的只有有序全局路径。
