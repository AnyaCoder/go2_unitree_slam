# Goalpoint 安全门控与初始化流程（2026-10-21）

## 1. 目的

原版 `localPlanner` 在 autonomy 模式下有 `goalX=0, goalY=0` 默认值，原版
`pathFollower` 又会在收到 `/path` 后保持 `pathInit=true`。两者组合可能导致：
在没有新 Goalpoint 时，狗站起来后重新执行旧路径，或朝错误的 `(0,0)` 运动。

本项目不修改上游 FAR/localPlanner/pathFollower 算法，而是在执行边界增加
`nav_dog/nav_safety_gate.py`：

```text
Go2 localPlanner
  -> /path
  -> Go2 pathFollower
  -> /nav/path_follower_request
  -> nav_safety_gate
  -> /api/sport/request
```

`pathFollower` 的上游输出话题被 launch 强制 remap。安全闸是唯一允许向真实
Sport API 发布本项目运动请求的节点。

## 2. 启动即关闭

安全闸进程每次启动都处于 `DISARMED`。它只接受：

```text
1003 StopMove
1008 Move
```

其它 Sport API 编号一律拒绝。

### 2.1 Goalpoint 前置条件

以下条件全部满足时，`/nav/goal_commands_ready=true`：

1. `/livox/imu` 有连续静止采样；
2. 采样窗口约 2.5 s、至少 100 帧、最大采样间隔不超过 0.20 s；
3. 三轴 gyro bias 最大绝对值不超过 0.03 rad/s；
4. 三轴 gyro std 最大值不超过 0.02 rad/s；
5. accel 均值向量模长在 9.00 ~ 10.60 m/s²；
6. 当前定位 epoch 收到新的 `/initialpose`；
7. 当前 epoch 之后出现 `Pose initialization successful` 或
   `Initializing Succeed`；
8. `/lio_sam_ros2/mapping/re_location_odometry` 在 1 s 内更新且位姿数值有限；
9. 首次取得定位锚点时，当前 odom 距所选 initial pose 不超过 5 m，且 yaw 差
   不超过 1.0 rad。锚点锁定后不再持续比较；狗正常走出 5 m 不会重新门控。

不满足时，狗端 `far_command_link.py` 会直接丢弃 TCP 8899 收到的
`/goal_point` 与 `/way_point`，不会把它们送进 localPlanner。

### 2.2 Move 前置条件

在 Goalpoint 前置条件之上，还必须同时满足：

1. 当前定位 epoch 收到新的 `/goal_point`；
2. 收到当前 goal 对应的 `/way_point`；
3. localPlanner 在 goal 之后生成新的非空 `/path`，并在 3 s 内继续刷新；
4. path 坐标全部有限；
5. IMU 和 odom 未超时。

Goalpoint 和 waypoint 在同一个定位 epoch/goal 内没有时间过期，避免 FAR waypoint
保持不变时被安全闸周期性中断。只有新 Goalpoint 会清空旧 waypoint/path，并要求
重新生成。当前 path 超过 3 s 未刷新、IMU/odom 超时或重新定位时，`motion_ready`
变为 false。`pathFollower` 若继续发 `Move`，安全闸会用 `StopMove` 替换；pathFollower
自己发出的 `StopMove` 始终可以透传。

## 3. 正确的真机初始化顺序

```bash
cd ~/go2_unitree_slam
./nav/start_far_real.sh
```

然后：

1. 狗站稳，保持完全静止约 3 秒；
2. RViz 点一次 `2D Pose Estimate`；
3. 等狗端出现 `Pose initialization successful` / `Initializing Succeed`；
4. 查看 `/nav/safety_status`，确认 `goal_commands_ready=true`；
5. 再点 FAR Goalpoint；
6. 等 `motion_ready=true` 后才允许底盘执行。

## 4. 查看门控状态

在狗端：

```bash
source /opt/ros/foxy/setup.bash
source /home/unitree/autonomy_stack_go2/install/setup.bash
timeout 3 ros2 topic echo /nav/safety_status std_msgs/msg/String \
  --qos-reliability reliable --qos-durability transient_local
```

关键字段：

```text
goal_commands_ready   IMU、初始位姿、定位前置条件
motion_ready          完整 goal/waypoint/path 运动条件
reasons               第一个阻止原因
imu.state             READY / COLLECTING / GYRO_BIAS / ...
initial_pose          当前 epoch 的 RViz 初始位置和 yaw
localization_confirmed
odom_age_s
path_age_s
```

常见原因：

| reason | 含义 | 处理 |
|---|---|---|
| `IMU_NOT_CALIBRATED` | IMU 采样不足或静止检查失败 | 让狗完全静止，检查 Livox IMU |
| `IMU_STALE` | `/livox/imu` 中断 | 检查 Livox/LIO 服务 |
| `INITIAL_POSE_REQUIRED` | 当前 epoch 没有初值 | RViz 点 2D Pose Estimate |
| `LOCALIZATION_NOT_CONFIRMED` | 定位尚未成功 | 等待 ICP / Pose initialization successful |
| `ODOM_STALE` | 重定位 odom 超时 | 检查 LIO/重定位 |
| `POSE_NOT_ANCHORED` | 首次锚定时 odom 距所选初值超过 5 m | 重新定位，禁止运动 |
| `ORIENTATION_NOT_ANCHORED` | 首次锚定时 odom yaw 与所选初值差超过 1.0 rad | 重新拉准狗头朝向并定位 |
| `GOAL_REQUIRED` | 当前 epoch 没有新 Goalpoint | 重新点 FAR Goalpoint |
| `WAYPOINT_REQUIRED` | 当前 goal 没有 FAR waypoint | 检查电脑 FAR 与 8899 |
| `PATH_REQUIRED/STALE` | localPlanner path 不存在或超过 3 s 未刷新 | 检查狗端 localPlanner |

## 5. 验收命令

```bash
cd ~/go2_unitree_slam
./nav/check_real_chain.sh
```

现在还必须满足：

```text
狗端 nav_safety_gate.py 进程存在
/api/sport/request 只有一个发布者
/nav/path_follower_request 至少有一个发布者
/nav/safety_status 可读取
goal_commands_ready=true
```

`motion_ready=false` 在尚未点 Goalpoint 时是正常状态，只产生 WARN；它表示狗不会被旧
路径带走。若已经点了 Goalpoint 仍然为 false，按 `reasons` 排查。

## 6. 已执行的自动化验证

纯状态机测试：

```bash
python3 -m unittest discover -s tests -v
```

覆盖：

- 初始状态必须关闭；
- 静止 IMU 校准通过后才允许输入 Goalpoint；
- initial pose 之前收到 Goalpoint 必须拒绝；
- 新的 initial pose 必须清空旧 goal/path；
- 一次性位置锚点锁定后，长距离行驶不得因距离初值过远撤销运动；
- Goalpoint/waypoint 在同一目标内不得按时间过期；
- 新 Goalpoint 必须要求新 waypoint 和新 path；
- path 超过 3 s 未刷新立即撤销运动；
- 没有 Goalpoint 时新 path 不能授权运动；
- gyro bias 超限和 accel 量纲错误不能校准；
- odom 距 initial pose 过远必须阻止；
- 非 `StopMove`/`Move` API 和非有限速度必须拒绝。

隔离 ROS domain 上的集成测试还验证了：

```text
未初始化 pathFollower Move -> StopMove
静止 IMU 校准 -> goal_commands_ready
initial pose + 定位成功 + odom -> Goalpoint ready
新 goal + waypoint + path -> Move 放行
path 超时 -> 后续 Move 被 StopMove 替换
```

该测试不连接狗，也不向真实底盘发布速度。

## 7. 边界与限制

- 这是执行层 fail-closed 门控，不替代底盘急停和物理遥控器接管。
- 正常 FAR 导航时，物理遥控器仍应保持可用；安全闸只在 pathFollower 尝试运动或已放行
  Move 的状态失效时发送停止。
- 启动检查若发现 `/api/sport/request` 发布者不是恰好一个，禁止进入运动模式。
- 修改 IMU 驱动校准、LIO、initial-pose 桥或 pathFollower 后，必须重新跑状态机测试、
  ROS 隔离集成测试和真机只读验收。
