# 真机 SLAM 冷启动、重定位与完整导航执行

> 权威文档：[`必看.md`](../必看.md)。更新：2026-10-22

## 1. 架构

```text
狗端：Livox/LIO -> pose；固定 PCD -> static_map_replay -> terrain -> FAR -> localPlanner
      -> pathFollower -> /api/sport/request

电脑：固定 PCD 背景 + 8898 只读显示 + 8899 Goalpoint + 8900 初始位姿
```

## 2. 成功判据

```text
狗端 UnitreeSlam / Livox / LIO 正在运行
狗端 static_map_replay / terrainAnalysis / terrainAnalysisExt / FAR 正在运行
狗端 localPlanner / pathFollower 正在运行
狗端输出 Pose initialization successful
电脑日志出现 first SLAM odometry received
电脑上 Go2 模型、odom 和关节状态持续更新
电脑上没有 pcdMapSim / terrain / FAR / localPlanner / pathFollower
狗端 /path、/way_point 和 FAR Marker 均唯一发布
/api/sport/request 只有 pathFollower 一个发布者
狗端没有 dog_control_B1_one / go2_control_by_sdk send_cmd
./nav/check_real_chain.sh 为 failure=0
```

## 3. 一键启动

```bash
cd ~/go2_unitree_slam
./nav/start_far_real.sh
```

脚本依次清理旧进程、禁用 UnitreeSlam 旧运动控制、启动狗端完整链、启动通信桥
和电脑显示。

## 4. 重定位

1. 在 RViz 点击 `2D Pose Estimate`。
2. 拖到狗在固定背景图中的位置和朝向。
3. 等待狗端 `Pose initialization successful`。
4. 确认电脑 `/state_estimation` 持续更新。

## 5. Goalpoint

重定位稳定后点击 `Goalpoint`：

```text
RViz /goal_point
  -> goal_sender.py
  -> TCP 8899
  -> far_command_link.py
  -> 狗端 /goal_point
  -> dog-side FAR
  -> /way_point
  -> localPlanner
  -> /path
  -> pathFollower
```

电脑只显示狗端生成的实际路径，不重新规划。

## 6. 防启动乱走

```text
localPlanner goalX/goalY 启动为 NaN
未点 Goalpoint -> 无有效 FAR /way_point -> 无 /path -> 狗不动
点到 Goalpoint -> 狗端自行生成 /way_point 和 /path
```

若无人发目标却发生运动：

```bash
./nav/stop_real_all.sh
```

然后检查 `/tmp/go2_nav_live_restart.log` 和旧运动控制进程。
